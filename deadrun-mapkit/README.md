# deadrun-mapkit

OSM 지도를 **타일로 구워** 정적 호스팅에 올리고, 앱에서 **필요한 타일만 받아** 쓰는 도구 모음.

Overpass API를 실시간으로 부르는 대신 미리 구운 바이너리를 쓴다.
서버는 필요 없다 — GitHub Pages·S3·R2 같은 **파일 저장소**면 된다.

> OSM 데이터는 **ODbL 라이선스**다. 배포물과 앱 화면에 `© OpenStreetMap contributors` 표기가 필요하다.

## 1. 왜 만들었나

앱이 매번 Overpass API를 부르면 이런 일이 생긴다.

```
WARN [DEADRUN] Overpass 미러 실패: overpass-api.de (HTTP 504)
WARN [DEADRUN] Overpass 미러 실패: kumi.systems (Fetch request has been canceled)
WARN [DEADRUN] Overpass 실패 → 합성 폴백
```

무료 공용 서버라 슬롯이 차면 504를 던진다. **버그가 아니라 정책이고 우리가 고칠 수 없다.**

| | Overpass 실시간 | 구운 타일 |
|---|---|---|
| 크기 (반경 1km 도로+건물) | 1,256 KB | **55 KB** |
| 네트워크 응답 | 2.0~2.9초 (3회 중 1회 504) | **56ms** (정적 파일) |
| 서버 장애 | 게임이 가짜 지도로 떨어짐 | 캐시로 계속 플레이 |
| 오프라인 | 불가 | **가능** |

디코드 + 도로 그래프 빌드 시간은 팩 크기에 비례한다.

| 팩 | 크기 | 디코드 | 그래프 빌드 | 합계 |
|---|---|---|---|---|
| 반경 1km | 55 KB | 3ms | 7ms | **10ms** |
| 반경 1.5km (도로 1,924 · 건물 2,399) | 140 KB | 4ms | 11ms | **15ms** |

## 2. 왜 중심좌표와 반경을 넣나

> "그냥 우리나라 전체 지도를 한 번에 요청하면 안 되나?"

결론부터 — **요청 자체는 됩니다.** 실제로 해봤다.

```
서울 전역 도로 한 번에 요청 (1,100km²)
  HTTP 200 · 17.0초 · 96 MB · way 171,323개
```

성공했다. 그런데도 타일로 나누는 이유가 넷 있다.

### ① 클라이언트가 전국을 받을 수 없다 (가장 큰 이유)

굽는 쪽이 아니라 **쓰는 쪽** 문제다.

폰이 게임을 켤 때마다 전국 270MB를 받을 수는 없다. 받았다 쳐도 전국 도로를
`RoadGraph`로 만들면 노드가 수백만 개라 메모리에 올라가지 않는다.

**결국 어디선가는 잘라야 한다.** 그러면 굽는 단계에서 잘라두는 게 맞다.
반경 1km 플레이에 필요한 건 z13 타일 1~4장, 약 100~300KB뿐이다.

### ② 실패하면 전부 잃는다

96MB를 17초 받다가 15초째에 끊기면 처음부터 다시다. 전국이면 1GB에 수 분이라
성공할 때까지 몇 번을 반복해야 할지 알 수 없다.

타일 단위면 **실패한 타일만** 다시 구우면 된다. `--resume`이 그래서 있다.

### ③ 일부만 다시 구울 수 있다

강남에 새 도로가 생겼을 때 전국을 다시 굽는 것과 타일 몇 장만 다시 굽는 것은
완전히 다른 일이다.

### ④ Overpass 사용 정책

Overpass는 **편집자·연구자를 위한 질의 엔진**이지 대량 다운로드 창구가 아니다.
자원봉사 서버 몇 대가 전 세계 요청을 받고 있다. 공식 안내도 대량 추출이 필요하면
Overpass 대신 **Geofabrik 추출본**을 쓰라고 되어 있다.

### 그래서 전국은 어떻게 하나

두 가지 길이 있다.

**(a) 권역별로 나눠 굽기 — 지금 도구로 가능**

```bash
npm run mapkit -- bake --bbox 126.76,37.42,127.18,37.70 --resume   # 서울
npm run mapkit -- bake --bbox 128.90,35.05,129.30,35.30 --resume   # 부산
npm run mapkit -- bake --bbox 127.30,36.25,127.50,36.45 --resume   # 대전
```

같은 `--out`·`--version`을 쓰면 매니페스트가 누적된다. 시간은 걸리지만 확실하다.

**(b) Geofabrik `.osm.pbf`를 입력으로 쓰기 — 아직 미지원**

한국 전체가 압축된 바이너리 **287MB 한 파일**이고 매일 갱신된다.
네트워크 요청 한 번으로 전국이 손에 들어오므로 전국 규모라면 이쪽이 정석이다.

지금 도구는 Overpass만 읽는다. 전국을 제대로 하려면 `src/osm.ts` 옆에
`src/pbf.ts`를 붙이는 게 맞다. 필요하면 그때 만들면 된다.

> 요약: **중심좌표+반경은 Overpass의 한계 때문이 아니라, 쓰는 쪽(폰)이
> 통째로는 감당할 수 없기 때문이다.** 어차피 잘라야 하니 격자로 잘라둔다.

## 3. 설치와 실행

```bash
cd deadrun-mapkit
npm install
npm run admin
```

브라우저에서 **http://localhost:8787** 을 엽니다. 여기서 클릭만으로 다 됩니다.

```
┌─ 1 · 어디를 구울까 ──────────────────┐
│  강남 일대 / 서울 / 수도권 / 전국 …   │  ← 고르거나
│  지도에서 Shift+드래그로 직접 지정      │
│  [규모 계산하기]  → 타일 수·용량·시간   │
├─ 2 · 굽기 ─────────────────────────┤
│  버전 v1  ☑건물 포함  ☑이어서 굽기     │
│  [굽기 시작]   진행률·로그 실시간 표시   │
├─ 3 · 결과 파일 ─────────────────────┤
│  타일 12장 · 2.53 MB                 │
│  git에 올릴 것을 알려줌               │
├─ 4 · 앱에 연결 ─────────────────────┤
│  .env에 넣을 주소를 그대로 보여줌       │
└────────────────────────────────────┘
```

지도에 **구운 타일이 초록 사각형**으로 표시되고, 클릭하면 그 타일의 도로·건물이
실제로 어떻게 들어갔는지 **눈으로 확인**할 수 있습니다.

아래는 같은 일을 하는 CLI입니다. UI로 하는 게 편하면 건너뛰어도 됩니다.

### 3-1. 굽기 전에 규모부터 본다 (네트워크 안 씀)

```bash
npm run mapkit -- plan --center 37.5609,126.8394 --radius 3000
```

```
줌 z13 · 타일 3.88km (15.1km²) · 9개

  전부 도심이면          2.4 MB
  전부 소도시면          0.5 MB
  전부 농촌·산간이면      0.2 MB
```

타일 몇 장이고 대략 몇 MB인지 알려준다. 전국을 굽기 전에 꼭 한 번 돌려볼 것.

### 3-2. 굽는다

```bash
# 중심 + 반경으로
npm run mapkit -- bake --center 37.5609,126.8394 --radius 2500

# 사각 범위로
npm run mapkit -- bake --bbox 126.76,37.42,127.18,37.70
```

```
[1/6] 13/6981/3171  도로  937 · 건물 1108 →  73KB
[5/6] 13/6982/3172  도로 3117 · 건물 4594 → 246KB
완료: 타일 6개 · 0.9 MB
```

| 옵션 | 뜻 |
|---|---|
| `--out out` | 출력 폴더 (기본 `out`) |
| `--version v1` | 버전 폴더 이름 (기본 `v1`) |
| `--zoom 13` | 타일 줌 (기본 13 = 3.88km) |
| `--resume` | **이미 구운 타일은 건너뜀** — 중단 후 이어서 굽기 |
| `--no-buildings` | 도로만. 용량이 절반 가까이 준다 |
| `--delay 400` | 타일 사이 대기(ms). 공용 서버에 대한 예의이자 504 회피 |

### 3-3. 구운 결과를 확인한다

```bash
npm run mapkit -- info out/v1/13/6982/3172.drmp
```

```
out/v1/13/6982/3172.drmp  246 KB
타일 13/6982/3172
기준점 37.56199, 126.84814
도로 3117 · 건물 4594 · 좌표점 47,537
레이어 지하 43 / 지상 3017 / 고가 57
스폰 가능 도로 2783
```

### 3-4. 앱과 연결해 시험한다

```bash
npm run mapkit -- serve out
#   http://localhost:8787/  →  .../out
```

PC의 IP를 확인해서 앱 `.env`에 넣으면 실제 기기로 시험할 수 있다.

```
EXPO_PUBLIC_MAP_PACK_URL=http://192.168.0.10:8787
```

### 3-5. 자체 검증

```bash
npm test
```

포맷 왕복, 재투영 정확도, 손상 데이터 거부, 클라이언트 캐시 동작까지 23건을 검사한다.

## 4. 파일이 저장되는 구조

### 4-1. 굽고 나면 (`out/`)

```
out/
├── latest.json                    ← 매니페스트. 앱이 제일 먼저 읽는다
└── v1/                            ← 버전 폴더
    └── 13/                        ← 줌 레벨
        ├── 6981/                  ← 타일 X
        │   ├── 3171.drmp          ← 타일 Y. 여기가 실제 지도 데이터
        │   ├── 3172.drmp
        │   └── 3173.drmp
        └── 6982/
            ├── 3171.drmp
            ├── 3172.drmp
            └── 3173.drmp
```

경로가 `버전/줌/X/Y.drmp`인 이유는 **앱이 계산만으로 주소를 만들 수 있게** 하기 위해서다.
내 위치가 (37.5609, 126.8394)라면

```
z13 → x = 6982, y = 3172
→ https://내호스팅/v1/13/6982/3172.drmp
```

검색도, 서버 로직도 필요 없다. 그냥 정적 파일 한 장을 받는다.

### 4-2. `latest.json`이 하는 일

```json
{
  "format": "drmp",
  "formatVersion": 1,
  "version": "v1",
  "zoom": 13,
  "tilePath": "v1/{z}/{x}/{y}.drmp",
  "tileCount": 6,
  "totalBytes": 943932,
  "bbox": { "west": 126.811, "east": 126.868, "south": 37.538, "north": 37.583 },
  "attribution": "© OpenStreetMap contributors",
  "license": "ODbL 1.0",
  "tiles": {
    "13/6981/3171": 74596,
    "13/6981/3172": 120728,
    "13/6982/3172": 246387
  }
}
```

`tiles` 목록이 핵심이다. **실제로 존재하는 타일과 각각의 바이트 수**가 들어 있다.

- 바다·산속처럼 데이터가 없는 타일은 목록에 없다 → 앱이 **요청조차 하지 않는다**
- 받은 파일 크기를 목록과 대조해 **중간에 끊긴 다운로드를 잡아낸다**

### 4-3. `.drmp` 파일 하나의 속

```
헤더 40바이트
   0  magic 'DRMP'   4B
   4  version        1B
   6  quantMm        2B   좌표 1단위의 mm (250 = 0.25m)
   8  originLat      8B   이 타일의 기준점 위도
  16  originLon      8B   기준점 경도
  24  roadCount      4B
  28  buildingCount  4B
  32  z,x,y          어느 타일인지 스스로 기록

레코드 (도로 전부 → 건물 전부)
  u8  kind     도로 종류 인덱스 / 건물은 255
  i8  layer    -1 지하 · 0 지상 · 1 고가
  u16 pointCount
  i32 x0, y0                첫 점
  (n-1) x (i16 dx, i16 dy)  이후 점은 직전 점과의 차이
```

**왜 이렇게까지 하나** — 좌표 하나를 `double` 두 개로 두면 16바이트다. 위와 같이
0.25m 정수로 양자화하고 차분으로 담으면 **점당 4바이트**가 된다. 같은 지도가
JSON 1,256KB에서 55KB로 줄어드는 이유의 대부분이 여기 있다.

양자화 오차는 최대 12.5cm인데, 도로 그래프가 어차피 0.5m 격자로 노드를 병합하므로
게임 판정에 영향이 없다.

> **주의:** `kind`는 **인덱스**로 저장된다. `src/format.ts`의 `HIGHWAY_KINDS` 배열 순서를
> 바꾸면 이미 배포한 팩을 읽을 수 없다. 종류를 추가할 때는 반드시 **배열 끝에** 붙일 것.

### 4-4. 기기에 저장될 때

앱은 받은 타일을 문서 디렉터리에 **같은 경로 구조로** 남긴다.

```
<앱 문서 디렉터리>/
└── maps/
    ├── latest.json                ← 매니페스트 사본 (오프라인 대비)
    └── v1/13/6982/3172.drmp
```

**버전 폴더를 경로에 그대로 쓰는 것이 핵심이다.** 나중에 v2를 올려도 경로가 달라
옛 파일과 섞이지 않는다. 같은 경로를 덮어쓰면 기기는 "이미 받았다"고 판단해
옛 데이터를 계속 쓰게 된다.

### 4-5. 실행할 때 벌어지는 일

```
① latest.json 확인 (없으면 기기에 저장된 사본)
② 내 GPS → 덮어야 할 타일 번호 계산
③ 타일마다:  기기에 있나?
              ├ 있음 → 그대로 사용 (네트워크 안 씀)
              └ 없음 → HTTPS GET → 크기 검증 → 저장
④ 모든 타일을 "지금 내 위치" 기준으로 재투영해 하나로 합침
⑤ RoadGraph.build() → 기존 게임 로직 그대로
```

**두 번째 실행부터는 네트워크를 쓰지 않는다.** 지하철이나 산속에서도 진짜 지도로 플레이된다.

타일마다 기준점이 다르기 때문에 ④의 재투영이 필요하다. 같은 `playOrigin`으로 맞추지 않으면
타일 경계에서 도로가 어긋나 붙는다. (검증: 1km 떨어진 원점에서 오차 3.3cm)

## 5. 앱에 반영하는 법

### 5-1. 이미 붙어 있는 부분

`deadrun-expo`에는 단일 팩을 받는 기능이 이미 들어가 있다.

```
EXPO_PUBLIC_MAP_PACK_URL=https://내호스팅
```

주소만 넣으면 로딩 순서가 **지도 팩 → Overpass → 합성 도시**로 바뀐다.
`deadrun-expo/src/services/mapPack.ts`가 그 일을 한다.

### 5-2. 타일 방식으로 올리려면

여러 타일을 받아 합치려면 이 툴킷의 `MapClient`를 쓴다.
플랫폼에 의존하지 않으므로 **저장소만 끼워주면** 된다.

```ts
// deadrun-expo/src/services/tileStorage.ts (신규)
import { Directory, File, Paths } from 'expo-file-system';
import type { TileStorage } from '../core/mapkit/client';

export const expoStorage: TileStorage = {
  has:   async k => new File(Paths.document, 'maps', k).exists,
  read:  async k => await new File(Paths.document, 'maps', k).bytes(),
  write: async (k, d) => {
    const f = new File(Paths.document, 'maps', k);
    new Directory(f.parentDirectory).create({ intermediates: true });
    f.write(d);
  },
  remove: async k => new File(Paths.document, 'maps', k).delete(),
};
```

```ts
// game.init() 안에서
import { MapClient } from '../core/mapkit/client';

const client = new MapClient({
  baseUrl: Config.mapPackUrl,
  storage: expoStorage,
  log: msg => console.warn('[MAP]', msg),
});

const { ways, buildings } = await client.loadAround(origin, cfg.radiusMeters);
if (ways.length > 0) {
  this.graph = RoadGraph.build(ways);   // ← 기존 코드 그대로
  this.buildings = buildings;
  this.usingOsm = true;
}
```

`ways`의 타입은 `deadrun-expo`의 `RoadWay`와 같은 모양이라 **그래프부터 아래는 손댈 것이 없다.**
A*, 좀비 추격, GPS 맵매칭, 시야 차단 전부 그대로 돈다.

### 5-3. 참조 방식 정하기

위 예시는 `src/core/mapkit/`에 복사해 둔 것을 가정했다. 셋 중 하나를 고르면 된다.

| 방식 | 장단 |
|---|---|
| **파일 복사** (`src/core/mapkit/`) | 가장 단순. 지금 앱이 쓰는 방식. 포맷이 바뀌면 수동으로 맞춰야 함 |
| 상대 경로 임포트 | 복사가 없지만 Metro가 프로젝트 밖 파일을 읽도록 `watchFolders` 설정 필요 |
| npm 워크스페이스 | 정석이지만 Expo 설정을 건드려야 함 |

프로토타입 단계에서는 **복사**를 권한다. 포맷이 안정되면 워크스페이스로 옮기면 된다.
복사 대상은 `src/geo.ts`, `src/tiles.ts`, `src/format.ts`, `src/client.ts` 넷이다
(`osm.ts`·`bake.ts`는 굽는 쪽 전용이라 앱에 필요 없다).

## 6. 갱신과 운영

### 새 버전을 굽는다

```bash
npm run mapkit -- bake --bbox ... --version v2
```

`out/v2/...`가 새로 생기고 `latest.json`이 v2를 가리킨다.
기기에 남은 v1 파일과 **경로가 달라 섞이지 않는다.**

> **주의:** 이미 올린 버전 폴더를 절대 덮어쓰지 말 것.
> 기기 캐시와 섞여 반쯤 옛 데이터를 읽는 사고가 난다.

### 얼마나 자주 갱신하나

구운 팩은 **스냅샷**이라 현실의 도로가 바뀌어도 반영되지 않는다.
다만 도로망 토폴로지는 느리게 변한다 — 새 아파트 단지나 도로 개편은 분기 단위 사건이다.
**월 1회면 실사용에 충분하다.**

더 최신이 필요하면 **하이브리드**로 간다. 타일을 바탕으로 쓰고, 현재 위치 반경 300m만
Overpass로 조회해 덧입힌다. 실패해도 타일이 있으니 게임은 정상 진행된다.

### 전국 배포

GitHub Pages에 올리는 절차, 한도 대조, 저장소 비대화 방지는
[docs/github-pages.md](docs/github-pages.md)에 단계별로 적어두었다.

요약하면 — **전국 도로만 148MB, 건물 포함 270MB**로 GitHub 한도(파일당 100MB,
Pages 사이트 1GB) 안에 충분히 들어간다.
